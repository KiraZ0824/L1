# 积分中心功能说明

## 需求描述

积分中心面向平台运营管理者，用于统一管理系统积分（Remi Points，简称 RP）的**发放**与**项目预算管控**。

系统只做发放，不做收取，因此页面不提供"获得/消耗/个人余额"等个人账户视角，全部指标均以平台为发放主体、以项目预算为管控边界进行统计。积分与预算的换算口径为 1 RP ≈ 1 元。

页面由三部分组成：

1. 顶部概览区：发放视角 + 预算视角双栏并列
2. 发放概览卡片：发放明细、项目预算概览两个页签
3. 筛选与合计区：支持按关键词、状态、类型过滤发放台账，并实时汇总

| 功能点 | 说明 |
|---|---|
| 页面入口 | 侧边栏 → 积分中心 |
| 页面 ID | `page-points` |
| 页面标题 | 积分中心 |
| 副标题 | 系统积分发放管理 · 发放明细 · 项目预算管控（1 RP ≈ 1 元） |
| 渲染函数 | `renderPointsCenter()` |
| 数据来源 | `projects`（预算口径）、`pointsIssuanceRecords`（发放台账） |

## 顶部概览区

概览区为左右双视角布局，中间以竖线分隔。

### 发放视角（左）

| 字段名称 | 英文名称 | 说明 |
|---|---|---|
| 系统累计发放 | ptsTotalIssued | 平台自启用以来已发放的积分总量，取所有项目 `spent` 之和 |
| 本月发放 | ptsMonthIssued | 台账中最近一个发放月份内状态为"已发放"的积分合计 |
| 待发放（审批中） | ptsPendingIssued | 已进入审批流程但尚未实际发放的积分，取所有项目 `frozen` 之和 |
| 覆盖项目 | ptsProjectCount | 存在发放记录的项目数 / 项目总数 |

### 预算视角（右）

| 字段名称 | 英文名称 | 说明 |
|---|---|---|
| 预算总额 | ptsBudgetTotal | 所有项目预算 `budget` 之和 |
| 已发放 | ptsBudgetIssued | 已实际发放并计入项目消耗的积分 |
| 剩余预算 | ptsBudgetRemaining | 预算总额 − 已发放 − 待发放 |
| 预算使用率 | ptsBudgetUsage / ptsBudgetBar | （已发放 + 待发放）÷ 预算总额，以百分比与进度条呈现 |

### 卡片头部指标

| 字段名称 | 英文名称 | 说明 |
|---|---|---|
| 累计已发放 | ptsHeaderIssued | 与"系统累计发放"同口径，绿色强调 |
| 待发放（审批中） | ptsHeaderPending | 与"待发放"同口径，橙色强调 |

## 发放明细页签

展示系统发放台账，按发放时间倒序排列。

### 列表字段说明

| 字段名称 | 英文名称 | 说明 |
|---|---|---|
| 发放时间 | issuedAt | 积分发放或提交审批的日期 |
| 接收人 | receiver / dept | 积分接收人姓名（主行）与所属部门（副行） |
| 类型 | type | 发放类型：任务奖励 / 知识贡献奖励 / 项目里程碑奖励 |
| 来源 | project / item | 来源项目名称（主行）与具体发放事由（副行） |
| 发放积分 | amount | 本次发放的积分数量，已发放与待发放以"+号"表示发放方向，已驳回不带符号 |
| 状态 | status | 发放状态标签，带状态圆点 |
| 发放单号 | no | 台账唯一编号，用于搜索定位，不在列表中单独成列 |

### 状态说明

| 状态值 | 显示文案 | 样式 | 计入发放额 |
|---|---|---|---|
| issued | 已发放 | 绿色（`status-done`） | 是 |
| pending | 待发放 | 橙色（`status-pending_review`） | 否，计入待发放 |
| rejected | 已驳回 | 红色（`status-rejected`） | 否，仅留痕 |

### 筛选与合计

| 功能点 | 说明 |
|---|---|
| 关键词搜索 | `ptsKeyword` — 按接收人、部门、来源项目、发放事由、发放单号模糊匹配，输入即过滤 |
| 状态筛选 | `ptsStatusFilter` — 全部状态 / 已发放 / 待发放（审批中）/ 已驳回 |
| 类型筛选 | `ptsTypeFilter` — 全部类型 / 任务奖励 / 知识贡献奖励 / 项目里程碑奖励 |
| 排序规则 | 按发放时间倒序，最新记录置顶 |
| 实时合计 | `ptsListSummary` — 展示"共 N 条 · 已发放 X RP · 待发放 Y RP"，随筛选条件变化 |
| 渲染函数 | `renderPointsIssuance()` |

## 项目预算概览页签

按项目维度展示预算执行情况，用于核对发放是否超出预算。

| 字段名称 | 英文名称 | 说明 |
|---|---|---|
| 项目名称 | name | 项目名称，加粗显示 |
| 总预算 | budget | 该项目分配的积分预算总量 |
| 待发放（冻结中） | frozen | 已提交审批、预算已冻结但尚未发放的积分，橙色显示 |
| 已发放 | spent | 该项目已实际发放的积分，绿色显示 |
| 剩余 | budget − spent − frozen | 项目可用预算余额 |
| 使用率 | (spent + frozen) ÷ budget | 进度条 + 百分比，>80% 红色、>50% 橙色、其余绿色 |

| 功能点 | 说明 |
|---|---|
| 页签切换 | `switchPointsTab(el, tab)`，切换到本页签时触发 `renderProjectBudget()` |
| 容器 ID | `projectBudgetBody` |

## 数据口径与一致性规则

| 规则 | 说明 |
|---|---|
| 单一数据源 | 概览区与项目预算概览页签的预算类指标均由 `projects` 汇总计算，不另行维护静态数字 |
| 账实相符 | 发放台账中"已发放"记录按项目汇总后，与对应项目的 `spent` 一致；"待发放"记录汇总后与 `frozen` 一致 |
| 本月口径 | "本月发放"以台账中最近一个存在发放记录的月份为准，避免演示数据与系统当前月不一致导致显示为 0 |
| 驳回不计额 | 已驳回记录不进入任何发放金额合计，仅在台账中保留审计痕迹 |
| 只发放不收取 | 所有金额均为发放方向，页面不提供扣减、消耗、退回等入口 |

## 异常情况说明

| 异常场景 | 处理说明 |
|---|---|
| 筛选后无匹配记录 | 表格显示"暂无符合条件的发放记录"，不展示空白表格 |
| 关键词清空 | 立即恢复展示全部台账记录，合计同步刷新 |
| 项目预算为 0 | 使用率按 0% 处理，不做除法运算，避免显示 NaN 或无穷大 |
| 剩余预算为负数 | 数值照常显示并以红色提示超支，不截断为 0 |
| 台账与项目预算不一致 | 以项目预算数据为准，需回查台账记录是否漏登或重复登记 |
| 页签切换失败 | 保持当前页签内容不变，避免出现空白区域 |
| 数据加载失败 | 保留页面结构与概览骨架，指标显示为 0，不抛出空白页 |

## UI界面

### 页面结构

- 页面标题：积分中心
- 页面副标题：系统积分发放管理 · 发放明细 · 项目预算管控（1 RP ≈ 1 元）
- 概览区：橙色渐变卡片（`points-hero`），左栏发放视角大数字，右栏预算管控清单与使用率进度条
- 卡片区：标题"发放概览"，右上角展示"累计已发放 / 待发放（审批中）"两项汇总
- 页签区：发放明细、项目预算概览
- 筛选区：搜索框 + 状态下拉 + 类型下拉，右侧为实时合计文案
- 列表区：表格展示对应页签数据

### 视觉与交互

- 概览区大数字使用 48px 加粗白色字体，单位"RP"以小号字紧随其后
- 左右视角之间以半透明竖线分隔，视觉上明确"发放"与"预算"两条主线
- 接收人、来源均采用主行 + 副行两级信息展示，主行为关键主体，副行为归属信息
- 发放积分右对齐并加粗，颜色随状态变化：已发放绿色、待发放橙色、已驳回灰色
- 状态使用统一的状态标签样式（文字 + 圆点），与平台其他列表页保持一致
- 页签切换仅替换卡片内列表区域，概览区保持不动
- 使用率进度条颜色随阈值变化，>80% 红色、>50% 橙色、其余绿色
