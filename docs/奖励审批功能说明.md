# 奖励审批功能说明

## 功能概述

奖励审批是 Remi AI 平台中连接「知识贡献」「项目管理」与「积分体系」的核心枢纽模块。当知识上传者完成高质量知识贡献、或项目负责人需要对团队成员进行额外激励时，奖励积分的分配需经过审批流程，确保积分发放的公平性、透明性和可追溯性。

平台设计了三种奖励审批场景：

1. **知识贡献奖励审核** — 知识上传时设定了奖励积分，知识审核通过后自动触发奖励分配审核。审核人需确认贡献者名单及每人分得的具体积分，审核通过后积分自动发放到贡献者账户。

2. **任务审核奖励分配** — 任务设有奖励积分（`reward > 0`），审核人审核任务时同时确认奖励分配方案。默认按预计奖励平均分配给项目成员，审核人可调整每人分得积分。

3. **追加奖励审批** — 项目负责人在项目执行过程中，针对突出贡献的成员发起额外奖励申请，提交后进入审批队列，审核人审核通过后从项目预算中扣减并发放给被奖励人。

三种场景共享统一的审批规范：审核意见必填、支持分配金额调整、审核结果通过消息中心通知相关人员。

## 知识贡献奖励审核

### 触发条件

| 功能点 | 说明 |
|---|---|
| 触发前提 | 知识文档上传时设定了奖励积分（`reward > 0`） |
| 触发时机 | 知识审核流程全部通过后自动触发 |
| 触发函数 | `auditRewardTask(reviewId)` |
| 入口1 | 任务管理看板 → 待审核任务「审核」按钮 |
| 入口2 | 工作台 → 待审核事项列表 → 点击进入审核 |
| 入口3 | Overview Dashboard → 待审核事项 → 点击进入 |

### 审核详情面板

| 功能点 | 说明 |
|---|---|
| 面板类型 | 侧滑面板（`projectDetailPanel`） |
| 面板标题 | 「奖励审核详情 — 」+ 知识编号 |
| 审核状态 | 待审核（黄色标签+圆点） |
| 知识标题 | 审核对象名称 |
| 知识描述 | 灰底背景展示知识描述 |
| 知识上传人 | 信息展示 |
| 所属部门 | 信息展示 |
| 知识贡献者 | 信息展示，多人逗号分隔 |
| 所属项目 | 关联项目名称 |
| 知识来源 | 上传/API导入/系统生成等 |
| 上传时间 | 知识上传时间 |
| 知识类型 | 一级类型标签 + 二级类型标签 |
| 知识附件 | 附件文件列表（文件名+大小） |
| 审核流程 | 时间线展示已完成的审核环节（头像+时间+状态） |

### 奖励分配

| 功能点 | 说明 |
|---|---|
| 分配方式 | 默认按预计奖励平均分配给所有贡献者 |
| 首位贡献者 | 自动补齐余数（如500分3人：168+166+166） |
| 每行内容 | 贡献者下拉选择 + 分配积分输入 + 原因输入 |
| 金额修改 | 可调整每人分配金额，修改后原因输入框自动启用 |
| 删除行 | 可删除某个贡献者的分配行 |
| 添加人员 | 不支持（已移除），仅限已有贡献者 |
| 分配列表容器 | `auditRewardRows` |
| 行构建函数 | `_buildRewardRow(person, amount)` |

### 审核操作

| 功能点 | 说明 |
|---|---|
| 审核意见 | 文本域，必填（红色*标记） |
| 审核不通过 | `doRejectAudit()` — 驳回，记录驳回意见 |
| 审核通过 | `doApproveAudit()` — 通过，发放积分给贡献者 |
| 取消 | 关闭侧滑面板 |

## 任务审核奖励分配

### 触发条件

| 功能点 | 说明 |
|---|---|
| 触发前提 | 任务设有奖励积分（`t.reward > 0`） |
| 触发时机 | 任务负责人提交审核后，审核人打开审核面板时自动展示 |
| 触发函数 | `auditTask(id)` |
| 入口1 | 任务管理看板 → 待审核状态「审核」按钮 |
| 入口2 | 工作台 → 待审核事项列表 |
| 入口3 | Overview Dashboard → 待审核事项 |

### 审核详情面板

| 功能点 | 说明 |
|---|---|
| 面板类型 | 侧滑面板（`projectDetailPanel`） |
| 面板标题 | 「审核任务 — 」+ 任务ID |
| 任务详情 | 展示 `_taskDetailHtml(t)`（标题、优先级、项目、负责人、截止日期、奖励、交付形式、审核流程时间线） |
| 奖励分配 | 仅当 `t.reward > 0` 时展示，含分配说明文字 |
| 审核意见 | 文本域，必填（红色*标记），通过或驳回意见 |
| 审核不通过 | `doRejectAudit()` — 驳回，记录驳回意见 |
| 审核通过 | `doApproveAudit()` — 通过，发放积分给项目成员 |
| 取消 | 关闭面板 |

### 奖励分配列表

| 功能点 | 说明 |
|---|---|
| 展示条件 | 仅当任务 `reward > 0` 时显示 |
| 分配说明 | 标注「默认按预计奖励平均分配，改动需填原因」 |
| 成员来源 | 从项目关联任务的负责人中汇总（`_auditMembers`） |
| 分配方式 | 默认平均分配，首位补齐余数（如500分3人：168+166+166） |
| 每行内容 | 人员下拉选择 + 分配积分输入 + 原因输入 |
| 金额修改 | 修改金额时原因输入框自动启用（白色背景），未修改时禁用（灰色背景） |
| 删除行 | 可删除分配行（至少保留1行） |
| 添加人员 | 不支持（已移除） |
| 分配列表容器 | `auditRewardRows` |
| 行构建函数 | `_buildRewardRow(person, amount)` |
| 金额变更联动 | `onRewardRowChange(idx)` — 判断金额是否变更，联动启用/禁用原因输入框 |
| 删除行函数 | `removeRewardRow(idx)` |
| 审核通过存储 | `t.rewardAllocation = allocations` 保存分配方案 |

## 追加奖励审批

### 触发条件

| 功能点 | 说明 |
|---|---|
| 触发前提 | 项目处于执行阶段，项目预算有剩余 |
| 发起人 | 项目负责人 |
| 触发入口 | 项目管理列表 → 操作列「⋮」→ 追加奖励 |
| 触发函数 | `openBonusModal(projectId)` |
| 面板类型 | 侧滑面板 |

### 申请表单

| 功能点 | 说明 |
|---|---|
| 项目信息 | 显示项目名称和当前阶段 |
| 奖励分配列表 | 每行：人员下拉 + 积分输入 + 原因输入 |
| 添加人员按钮 | 已移除（不可添加额外人员） |
| 默认行 | 项目负责人作为第一行 |
| 审核人选择 | 下拉选择审核人（从所有用户中选） |
| 审核流程展示 | 展示审核人信息 |
| 提交函数 | `submitBonusRequest()` |
| 数据存储 | 存入 `bonusRequests` 数组 |

### 审核详情面板

| 功能点 | 说明 |
|---|---|
| 打开方式 | `openBonusReview(requestId)` |
| 面板标题 | 「审核奖励申请 — 」+ 项目名称 |
| 项目信息 | 项目名称 + 申请人 |
| 奖励分配列表 | 人员 + 金额(RP) + 原因，底部显示合计 |
| 审核意见 | 文本域，必填（红色*标记） |
| 审核不通过 | `doRejectBonus()` — 驳回，记录意见，通知申请人 |
| 审核通过 | `doApproveBonus()` — 通过，从项目预算扣减，发放积分 |
| 取消 | 关闭面板 |

## 审批流程设计

### 知识贡献奖励审核流程

| 功能点 | 说明 |
|---|---|
| 第1步 | 知识上传者提交知识文档（含奖励积分设定） |
| 第2步 | 知识审核流程启动（多级审核，每级审核人审核） |
| 第3步 | 知识审核全部通过 → 自动触发奖励分配审核 |
| 第4步 | 奖励审核人确认贡献者名单和分配金额 |
| 第5步 | 审核通过 → 积分发放到贡献者账户 |
| 第5步(替代) | 审核不通过 → 记录驳回意见，通知上传者 |

### 任务审核奖励分配流程

| 功能点 | 说明 |
|---|---|
| 第1步 | 任务负责人完成任务并提交审核 |
| 第2步 | 审核人打开审核面板，查看任务详情和奖励分配列表 |
| 第3步 | 审核人确认或调整每人分得的积分（修改需填原因） |
| 第4步 | 填写审核意见（必填） |
| 第5步 | 审核通过 → 积分发放给项目成员，分配方案存入 `t.rewardAllocation` |
| 第5步(替代) | 审核不通过 → 记录驳回意见，任务退回驳回状态 |

### 追加奖励审批流程

| 功能点 | 说明 |
|---|---|
| 第1步 | 项目负责人在项目管理页面发起追加奖励 |
| 第2步 | 选择奖励人员和分配金额，填写原因 |
| 第3步 | 选择审核人，提交申请 |
| 第4步 | 审核人收到待审核通知（消息中心） |
| 第5步 | 审核通过 → 从项目预算扣减，积分发放给被奖励人 |
| 第5步(替代) | 审核不通过 → 记录驳回意见，通知申请人 |

## 审核意见规范

| 功能点 | 说明 |
|---|---|
| 必填校验 | 所有审核意见均为必填，空则提示「请填写审核意见」 |
| 通过意见 | 需说明通过理由（如：交付物符合要求，积分分配合理） |
| 驳回意见 | 需说明驳回原因（如：贡献者名单有误，分配金额不合理） |
| 意见存储 | 审核通过存入 `opinion` 字段，驳回存入 `rejectReason` |
| 意见展示 | 在审核流程时间线中展示审核人和审核意见 |

## 消息通知

| 功能点 | 说明 |
|---|---|
| 追加奖励待审核 | 通知审核人：「来自 XX 的追加奖励申请，金额 XXX RP」 |
| 追加奖励已通过 | 通知申请人：「你的追加奖励申请已通过，共 XXX RP 已发放」 |
| 追加奖励已驳回 | 通知申请人：「你的追加奖励申请已被驳回，原因：XXX」 |
| 知识奖励审核结果 | 通知知识上传者和贡献者审核结果 |
| 通知容器 | 消息中心（`openMessageCenter()`） |
| 渲染函数 | `renderNotifMessages()` / `renderNotificationMessages()` |

## 数据结构

### 知识审核奖励数据（_knowledgeReviews）

| 功能点 | 说明 |
|---|---|
| id | 审核记录ID（如 kr2） |
| keyId | 知识编号（如 RemiKB002） |
| title | 知识标题 |
| desc | 知识描述 |
| uploader | 上传人 |
| dept | 所属部门 |
| contributor | 知识贡献者（逗号分隔） |
| project | 所属项目 |
| source | 知识来源 |
| uploadTime | 上传时间 |
| primaryType | 一级类型 |
| subTag | 二级类型 |
| reward | 预计奖励积分 |
| status | 审核状态（pending_review/done/rejected） |
| auditFlow | 审核流程节点数组 |
| files | 附件文件数组 |

### 追加奖励数据（bonusRequests）

| 功能点 | 说明 |
|---|---|
| id | 申请记录ID（如 br1） |
| projectId | 关联项目ID |
| requester | 申请人 |
| allocations | 分配列表（person + amount + reason） |
| reviewer | 审核人 |
| status | 审核状态（pending_review/approved/rejected） |
| opinion | 审核意见 |
| submitTime | 提交时间 |

### 奖励分配行数据（_auditMembers / _bonusMembers）

| 功能点 | 说明 |
|---|---|
| person | 人员姓名 |
| amount | 分配积分 |
| reason | 分配原因（修改金额时必填） |

## 关键函数

| 功能点 | 说明 |
|---|---|
| `auditRewardTask(id)` | 打开知识贡献奖励审核面板 |
| `_buildRewardRow(person, amount)` | 构建奖励分配行（知识奖励） |
| `onRewardRowChange(idx)` | 奖励分配金额变更时联动原因输入框 |
| `removeRewardRow(idx)` | 删除奖励分配行 |
| `doApproveAudit()` | 知识奖励审核通过 |
| `doRejectAudit()` | 知识奖励审核不通过 |
| `openBonusModal(projectId)` | 打开追加奖励申请面板 |
| `_buildBonusRow(person, amount)` | 构建追加奖励分配行 |
| `submitBonusRequest()` | 提交追加奖励申请 |
| `openBonusReview(requestId)` | 打开追加奖励审核面板 |
| `doApproveBonus()` | 追加奖励审核通过（扣减项目预算） |
| `doRejectBonus()` | 追加奖励审核不通过 |
| `renderNotifMessages()` | 渲染消息中心通知列表 |
